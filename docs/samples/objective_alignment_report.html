Testing Approach

Two tracks testing whether a system stays on the objective it was actually given, or drifts under a competing-objective pressure. Multi-hop QA: real HotpotQA bridge/comparison questions, requiring two chained facts to answer, each run baseline and with one hand-authored pressure (a tangential extra ask, an explicit reframing, or a decoy fact planted in context). Agentic: the same Mind2Web tasks and harness scenario 2 uses, single-shot rather than repeated, with pressure folded into the task instruction, in both single- and multi-agent mode. One shared LLM-judge rubric scores both tracks into four categories — on_goal, scope_creep, sub_goal_substitution, goal_abandonment — rather than a raw correctness score alone, since staying correct on an unrelated tangent is a different failure than staying correct on the actual ask.

Next Steps

  • This is a v1, hand-authored test suite (12 multi-hop pairs, 5 agentic task pairs) — not a validated adversarial benchmark. Whether these specific pressures reliably elicit drift, and how well the judge's four-way classification holds up under scrutiny, is what running this scenario checks, not something assumed going in.
  • No reasoning-path-adherence check yet (comparing the multi-hop response against HotpotQA's own supporting_facts annotation) — 'correct' currently only checks the final answer, not whether the system's stated reasoning actually engaged the right two entities to get there.
  • The agentic track's pressure is folded into a single-turn instruction, not injected mid-task — a true long-horizon drift test (per Arike et al. 2024) would apply pressure partway through a longer-running task, which neither sibling repo's agent loop currently exposes a hook for.
  • JUDGE_MODEL doing both the drift classification and (implicitly) the correctness check in one call trades a cleaner design for coupling — worth splitting into two calls if either signal needs independent validation later.
